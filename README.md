# 교실 리그

교사가 준비한 공용 태블릿에서 두 학생이 대결 결과를 함께 기록하는 교실용 웹앱입니다. 학생 개인 로그인은 없습니다.

## 실행

Node.js 24 이상이 필요합니다. Windows PowerShell에서는 다음 명령을 사용합니다.

```powershell
npm.cmd install
npm.cmd run dev
```

PC에서 [http://localhost:3000](http://localhost:3000)을 엽니다.

처음 화면에서 학급 이름, 학생 명단, 교사 비밀번호를 입력합니다. 학생은 6~100명이며, 각 리그에 최소 2명이 필요합니다.

### 체험 학급

서버를 실행한 상태에서 별도 터미널에서 아래 명령을 실행합니다.

```powershell
npm.cmd run demo
```

- 학급: **체험 학급 · 예시 30명**.
- 체험 학급 교사 비밀번호: **league2026**.
- 최초 배치가 완료된 예시 학급이며, 리그마다 예시 경기 1개가 있습니다.
- 같은 체험 학급이 있으면 명령을 다시 실행해도 덮어쓰지 않습니다.
- 실제 학급은 연결을 해제한 뒤 첫 화면의 **새 학급 만들기**로 별도 생성합니다.

### 태블릿 연결

교사 PC와 같은 네트워크의 태블릿에서 `http://교사PC의IPv4주소:3000`을 엽니다. PC의 주소는 `ipconfig`로 확인합니다. PC 서버가 실행 중이어야 하며, Windows 방화벽에서 해당 연결을 허용한 환경이어야 합니다.

태블릿에서 학급을 선택하고 교사 비밀번호로 한 번 연결하면 공용 모드를 유지합니다. 각 학생은 이름만 선택합니다. 서버에 저장하므로 태블릿 여러 대가 같은 학급 기록을 공유합니다. 다른 기기에서 변경한 데이터는 최대 15초 안에 화면에 반영되며, 저장할 때는 서버의 최신 기록을 검증합니다.

## 수업 운영

1. **교사 관리 → 학생·배치:** 명단과 배치전 일정을 확인합니다. 배치전 기본은 2일, 학생당 4경기입니다.
2. **공용 모드:** 학생들이 배치전 후 두 사람의 이름·승자를 선택하고 함께 확인합니다.
3. **학생·배치:** 승리 수, 동점, 결석을 확인하고 첫 리그를 확정합니다. 배치전을 생략하고 교사가 직접 배정하는 것도 가능합니다.
4. **시즌·승강:** 시즌과 승급 기간 1~3회, 각 단계 경기 수, 리그 경계별 교환 인원을 설정합니다.
5. **공용 모드:** 같은 리그에서 대결합니다. 리그전은 승리 +10 RP, 승급 기간은 지정 대진으로 승리 +15 RP입니다.
6. **시즌·승강:** 승급 기간 종료 또는 지정 경기 전체 완료 후 승강을 미리 보고 확정합니다. 경계 동점은 순서를 정하고 확인합니다.
7. 마지막 구간은 이번 시즌의 리그별 최종 순위를 보존하고 다음 시즌 소속을 별도로 저장합니다.

### 기록·관리 규칙

- 두 학생의 현장 확인을 마쳐야 저장됩니다. 버튼을 누른 사람을 개인별로 인증하는 방식은 아닙니다.
- 저장된 경기 한 번은 두 학생의 경기 기회를 각각 1회 사용합니다.
- 동일 상대 제한과 경기 기회는 **리그전·승급 기간 각각** 적용합니다. 두 단계 RP는 같은 구간에 합산합니다.
- 중복 저장, 한도 초과, 다른 리그 대결, 지정 대진 위반을 서버에서 차단합니다.
- 결과 입력 도중 학생이나 승자를 바꾸면 두 확인을 초기화합니다. 미완료 입력은 2분 동안 사용하지 않으면 초기화됩니다.
- 저장 후 결과를 보여 주고 5초 뒤 홈으로 돌아갑니다.
- 교사 관리에서 이유를 남겨 승자를 정정하거나 경기를 취소합니다. 취소하면 경기 기회가 복원됩니다.
- 마감한 경기·순위는 수정하지 않습니다. 이미 기록이 있는 단계의 날짜·경기 수와 적용한 승강도 보호합니다.
- 중간 승강 후 RP·연승 횟수는 새 구간에서 0부터 시작합니다. 이전 기록과 배지는 남습니다.
- 자동 훈장은 구간 내 3연승, 실제 상위 소속 적용 시 승급 성공입니다.
- **교사 관리 → 커스텀 훈장 → 훈장 만들기**에서 이름·색상·설명·수여 기준을 정해 미리 저장합니다. 기본 6색 팔레트나 직접 색상 선택기를 사용할 수 있습니다. **학생에게 수여**에서 저장된 훈장과 받을 학생을 선택합니다. 같은 훈장을 여러 학생에게 수여할 수 있으며, 회수해도 저장된 훈장은 유지됩니다.
- 관리 권한은 공용 모드로 전환하면 즉시 폐기됩니다. 관리 화면은 5분간 사용하지 않으면 잠기며, 서버 관리 세션도 최대 15분 뒤 만료됩니다.

## 저장과 실행 환경

외부 배포 구성과 계정 준비 순서는 [배포 준비 안내](DEPLOYMENT.md)에 정리했습니다.

- 화면·서버: Next.js, React, TypeScript.
- 저장: Supabase PostgreSQL. `DATABASE_URL`이 없는 로컬 개발 환경은 Node.js 내장 SQLite(`data/class-league.sqlite`)를 사용합니다.
- 비밀번호는 scrypt 해시, 기기·관리 세션은 서버 저장 방식입니다.
- 한 학급의 기록 변경을 트랜잭션 안에서 처리합니다. PostgreSQL에서는 학급 행을 잠가 동시 입력 때도 점수·횟수를 함께 검증합니다.
- Vercel에서는 `DATABASE_URL`이 반드시 필요합니다. 누락되면 임시 SQLite 파일로 기록을 저장하지 않고 오류를 반환합니다.
- Supabase의 `class_league` 전용 스키마는 서버만 사용하며, 익명·학생 API 접근 권한을 부여하지 않습니다.
- `CLASS_LEAGUE_DB`로 저장 경로를 바꿀 수 있습니다. `.env.example`을 참고합니다.
- HTTPS 서버에서는 `COOKIE_SECURE=1`을 설정합니다.

교사 관리의 **활동 설정 → 학급 기록 JSON 내려받기**로 기록을 내보낼 수 있습니다. 서버 데이터 전체를 복사하려면 서버를 종료한 뒤 `data` 폴더를 백업합니다. JSON 가져오기나 비밀번호 복구 화면은 이 버전에 포함하지 않았습니다.

## 검증

```powershell
npm.cmd test
npm.cmd run typecheck
npm.cmd run build
```

자동 검증은 경기 점수·기회·중복, 대진 가능성, 동점 승강, 구간 초기화, 최종 순위와 다음 시즌 소속, 결과 정정·배지 재계산, 교사 권한·학급 분리·동시 저장을 확인합니다.

배포용 실행:

```powershell
npm.cmd run build
npm.cmd start
```
